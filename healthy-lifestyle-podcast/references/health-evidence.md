# 健康证据、结论台账与审稿

## 本文件的用途

用于把健康问题转成可核查的科普对话。医学结论需要本集实际查证，不能从节目方法、既有脚本或主持人设定中继承。
处理用户资料时保留其来源和时间；检索不到或无法读取的材料必须标明限制。
一般科普建议应保持适用人群和前提，涉及个体诊疗决定时不得根据有限材料替代临床评估。

## 结论台账

每个影响健康判断或行为的关键说法建立稳定 `claim_id`；同一结论可被多个回合引用。
一个论断拆成可独立核对的单元，避免将结果、机制和行动建议装进同一条而掩盖推断。

| 字段 | 内容 |
|---|---|
| `id` | 稳定结论 ID，例如 `claim-001` |
| `statement` | 准备表达的准确结论，含必要限定 |
| `sources` | 来源 ID 或可访问链接，能定位到支持结论的正文、表或章节 |
| `source_date` | 发表或最近更新日期；未知时如实标记 |
| `accessed_at` | 本次实际读取日期，不能把检索摘要当全文读取 |
| `study_type` | 指南、系统综述、随机试验、观察研究、机制研究等 |
| `population` | 人群、纳排条件、情境及样本范围 |
| `result` | 比较对象、结局、效果量、分母、随访时间及不确定性 |
| `limitations` | 偏倚、混杂、精确度、外推、替代指标等关键局限 |
| `applicability` | 谁适用、谁可能不同；与目标听众的差异 |
| `certainty` | 来源的正式证据分级，或对研究性质与局限的描述 |
| `conflicts` | 资金来源、作者或机构利益关系；未知应写明 |
| `spoken_caveat` | 必须进入口播的限制条件及对应回合 ID |
| `turn_ids` | 使用该结论的脚本回合 |
| `review` | 实际核对者或工具、日期、结论、未解决问题 |

字段可按材料类型简化；健康建议的来源、人群、结果、局限和口播位置不能空缺而无解释。
结构化格式以 episode-format.md 定义为准；此表规定内容含义，不要求重复存储相同数据。

## 查证流程

1. 将主问题明确成目标人群、比较或暴露、关注结局和时间范围；找出会影响行动的子问题。
2. 优先读取与问题匹配的现行临床或公共卫生指南、系统综述；必要时回溯关键原始研究。
3. 用官方机构、研究发布方和期刊原文核对；媒体、节目及搜索摘要用于发现线索。
4. 核对标题与正文是否一致，研究实际测量了什么，比较对象、效应及局限是什么。
5. 重要建议查找相互独立的支持材料；发现分歧时比较人群、干预、结局与研究质量。
6. 按能支持的强度写结论，再设计口播表达；证据不足时缩小结论或说明未知。
7. 将关键限制放进实际使用该结论的附近，避免全放在节目末尾或文字说明里。

指南的地区、人群、发布日期、更新状态及利益关系均影响适用性，不能只凭机构声望判断。
当用户给出的资料已过时，查找后续更新并解释关键变化。无法完成核实时交付已完成部分和明确缺口。
对仍有争议的问题，说明争议来自哪里，不把双方观点自动摆成同等可信。
不把不同研究的数字自行拼成新的估算，除非计算方法、输入和适用条件透明且合理。

## 证据语言

| 材料能支持什么 | 口播应怎样说 |
|---|---|
| 观察到相关性 | 描述“有关联”及可能混杂，避免直接说“导致” |
| 合理机制或动物实验 | 明确是机制解释或特定实验，不能直接推出人体获益 |
| 随机试验 | 说明研究人群、干预、比较和实际结局，注意样本及随访局限 |
| 替代指标改善 | 讲清指标是什么，不自动升级为寿命、发病率或生活质量改善 |
| 平均效果 | 提醒个体反应和目标人群可能不同，避免承诺人人获益 |
| 未达到统计显著 | 不能直接断言无效；结合区间、样本与临床重要性说明 |
| 来源有正式分级 | 准确引用其分级及对象，不能自行套用 GRADE 名称 |

没有正式证据分级时，以普通语言描述研究类型和不确定性，不冒充完成了系统评价。
个人经验可说明处境和疑问，不能代替疗效证据；用户提供的真实经历也应避免过度外推。

## 风险、数字与行动建议

- 尽量提供绝对风险、基线、时间范围和一致分母；相对风险可作为补充。
- 来源缺少基线时说明缺失，不能编造；不将不确定估计读成确定事实。
- 百分比与百分点区分清楚；剂量、单位、频次和比较方向逐项核对。
- 示意计算必须明确标为假设，不能写成研究结果或真实病例。
- TTS 改写数字、缩写和单位后，与原始文本比对，特别检查否定词、小数点和范围。
- 行动项必须能从证据推出，说明适用条件；数量按主题控制，优先可开始的小步骤。
- 涉及停药、改剂量、检查或治疗选择时，说明何处需要个体评估，不提供无依据的统一方案。
- 症状和就医信号只在主题相关时加入，并依据已查证来源准确表达。

## 来源、商业关系和人物边界

记录产品销售、补充剂品牌、节目赞助、研究资助及作者利益关系，补充独立证据。
商业关系不自动推翻研究，但会影响交叉核查和表达方式；听众作选择所需的信息应公开。
不得虚构论文、链接、作者、数据、受访者、医生资历、临床经验、患者或“听友来信”。
需要生活场景时写成明确的假设情境；经用户提供的真实材料按授权范围使用。
阿衡与知夏均为内容主持人，声音和表现不能被包装成真实医学专家背书。
节目说明应如实说明合成声音；不能伪造采访、现场录音或真实个人发言。

## 独立审稿与验收记录

写稿和事实核查采用不同任务视角；可用独立子代理核查，给予来源、台账和脚本。
独立核查不应只询问“是否没问题”，应逐项检查可观察的断言、推断、数字和缺失条件。
审稿至少覆盖以下项目：

- 每个关键健康断言能否追到实际读取的来源，来源是否支持同等强度的说法。
- 因果、相关、机制和经验是否区分；人群、比较、结局、时间是否保留。
- 行动建议是否超出证据；分歧、局限和必要的就医边界是否准确。
- 脚本中重要限制是否真正进入配音文本；两位主持是否提供了虚构身份或案例。
- 口播数字与台账是否一致；配音改写是否改变药名、剂量、单位或否定词。
- 来源链接是否可核对，未读全文、无法访问和未解决问题是否如实记录。

记录实际完成的检查、执行者类型、范围、日期和结果；“AI 交叉核查”应如此称呼。
自动验证只证明它实际检查的结构和完整性，不能据此宣称医学审查、人工审稿或人工听审完成。
回听状态与内容核查状态分别记录。没有音频听觉能力或无人回听时，明确标记待回听。
修改关键结论后，重新核对受影响的台账、回合、说明和音频；缺段时不得交付为完整节目。

## 方法参考

以下是写作与核查方法的参考，每期医学结论仍须另行查证。

- [CDC 风险沟通原则](https://www.cdc.gov/public-health-risk-communication/php/about/understanding-and-applying-risk-communication-principles.html)：参考其已知与未知、风险背景和清楚表达的原则。
- [Cochrane 通俗摘要规范](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/guidance-writing-cochrane-plain-language-summary.pdf)：参考普通语言、证据可信程度与局限的表达方法。
- [Science Vs 节目页](https://podcasts.apple.com/us/podcast/science-vs/id1051557000)：参考制作、研究与事实核查分工及来源公开的做法。
- [碳基生物生存指南](https://www.xiaoyuzhoufm.com/podcast/64d8b36380c9ec4c5f22d225)：参考口播解释与文字文献入口分层呈现。
- [DeerFlow podcast-generation](https://github.com/bytedance/deer-flow/blob/main/skills/public/podcast-generation/SKILL.md)：参考结构化脚本与音频、文字稿共同交付；本 Skill 加入健康结论追溯。
