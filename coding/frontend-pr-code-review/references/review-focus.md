## 前端规模与风险

只计算和评估 PR 的前端部分，不要用整个 PR 的规模替代。

### Small

同时满足：

- 影响一个局部组件、hook 或客户端路径；
- 不改变共享状态、公共前端契约、路由或持久化格式；
- 不涉及异步竞态、缓存一致性、SSR/水合、安全边界或生产依赖；
- 行为和验证可以在一个紧凑功能卡片中解释。

### Medium

符合任一情况：

- 跨多个组件或 hooks 完成一个前端功能；
- 修改共享状态、查询缓存、API 使用或通用组件；
- 需要正常、异常和边界测试矩阵；
- 回归可能影响一个完整用户流程。

### Large

符合任一情况：

- 跨页面、应用模式、前端包或多个用户流程；
- 修改公共前端契约、路由、持久化、权限展示或渲染架构；
- 涉及 SSR/CSR 边界、流式 UI、复杂缓存或全局状态迁移；
- 无法通过单一前端调用链完整解释。

### 风险提升项

出现以下内容时至少提升一级审查深度：

- 登录、权限展示、租户信息或敏感数据；
- localStorage、IndexedDB、URL 状态或不可逆用户操作；
- API、事件、SDK 类型或跨版本兼容；
- 异步竞态、取消、重试、乐观更新、幂等或缓存一致性；
- HTML、Markdown、URL、文件上传、剪贴板或外部输入；
- SSR、水合、浏览器兼容、动态 import 或生产依赖；
- 大列表、流式渲染、音视频、图表或性能关键路径。

## 通用前端检查

所有类型都检查：

- 用户操作是否能沿入口、状态、请求和渲染走到预期结果；
- loading、empty、error、disabled、取消和重复操作；
- 组件卸载、快速切换和旧异步回调是否造成陈旧状态；
- 查询键、失效、分页、重试和缓存是否一致；
- 类型、运行时数据和 API 可空性是否一致；
- 权限是否只隐藏 UI，却未处理不可用或失败状态；
- 键盘、焦点、语义、ARIA、对比度和屏幕阅读器；
- 长文本、i18n、RTL、窄屏、溢出和动态高度；
- 测试是否验证用户行为，而不是只验证 mock 或内部实现；
- diff 是否包含无关前端改动或遗漏调用点。

## 按改动类型检查

### Feature Add

核心问题：新前端能力是否完整且正确地接入用户流程？

- 验证入口、可发现性和端到端交互。
- 检查未启用、未配置或无权限时旧 UI 是否保持。
- 检查 loading、empty、error、disabled、取消和恢复。
- 验证组件状态、查询缓存、API 和持久化一致。
- 覆盖正常路径和至少一个关键边界。

### Feature Change

核心问题：新 UI 行为是否正确，同时没有意外破坏旧用户路径？

- 明确 Before 和 After。
- 列出受影响页面、调用方、旧缓存、旧 URL 和已有持久化数据。
- 检查兼容、迁移、feature flag、降级和恢复。
- 验证新旧组件或请求路径并存时不会状态分叉。
- 同时覆盖旧场景与新场景。

### Bug Fix

核心问题：是否找到前端根因，并在正确层级修复？

- 建立可复现的用户或浏览器路径。
- 区分修复根因与隐藏错误、吞掉异常或强制刷新。
- 搜索同一 hook、共享组件或查询层的相邻路径。
- 检查修复是否引入无限重试、陈旧缓存或静默失败。
- 要求回归测试在旧实现失败、修复后通过。
- 判断是否需要清理 localStorage、缓存或残留 UI 状态。

### Refactor

核心问题：用户行为和前端契约是否等价，新结构是否降低复杂度？

- 写明渲染、事件、状态和副作用不变量。
- 检查 props、context、store、query key 和错误语义。
- 确认所有组件和调用点迁移完整。
- 检查重复实现、兼容层和死代码。
- 判断抽象是减少复杂度，还是增加组件/hook 间接层。
- 如果存在用户可见变化，重新分类为 Feature Change。

### Optimization

核心问题：前端收益是否可测量，同时保持交互和渲染正确？

- 验证实际瓶颈和一致基线。
- 检查渲染次数、commit 时间、网络、内存、包体积和尾延迟。
- 检查 memo、缓存、懒加载、虚拟化和批处理的陈旧状态风险。
- 验证焦点、动画、流式内容、折叠状态和事件顺序不变。
- 要求可重复 benchmark 或性能回归保护。

### Test

核心问题：测试是否能捕获真实前端回归？

- 判断测试在错误实现下是否会失败。
- 优先断言用户可见结果和可访问语义。
- 避免只断言 mock 调用次数、className 或内部 state。
- 覆盖异步、错误、边界、卸载和恢复路径。
- 检查 fake timer、网络 mock 和 DOM 清理的稳定性。

### Chore, Build, Dependency

核心问题：前端工程变化是否必要、可复现、安全且可回滚？

- 检查 Node、包管理器、lockfile、bundler 和浏览器目标。
- 检查生成产物、tree-shaking、bundle split 和运行时兼容。
- 检查供应链、许可证和 transitive dependency 风险。
- 验证 CI、本地、SSR 和生产构建的一致性。

### Docs and Style

- 文档必须匹配当前 UI、参数、默认值和错误状态。
- 示例必须可运行且不包含敏感信息。
- Style 改动必须确认没有 DOM、布局或行为变化，并避免扩大 review 噪音。

## 前端风险叠加项

只选择与当前功能最相关的最多两个：

- React 状态与副作用：依赖数组、闭包、render 中更新、清理和 remount。
- 数据请求与缓存：query key、分页、失效、重试、乐观更新和错误恢复。
- SSR 与浏览器：水合、server/client 边界、window API 和跨浏览器行为。
- 可访问性：键盘、焦点、ARIA、语义结构、缩放和屏幕阅读器。
- 国际化与布局：长文本、复数、RTL、溢出、窄屏和动态高度。
- 性能：重复渲染、大列表、流式更新、重型依赖、图表和包体积。
- 契约：可空字段、错误码、旧响应、序列化和运行时校验。
- 安全与隐私：XSS、Markdown、URL、文件、凭据、日志和敏感状态。

## 小改动固定卡片

下钻 Small 前端功能时使用：

```markdown
# <id> — <功能名称>

- Type: <change type>
- Verdict: <Pass | Issues | Not fully verified>
- Core check: <回答该类型最关键的问题>
- Frontend code: <关键代码链接>
- User risk: <主要回归风险>
- Verification: <已检查和已运行的前端验证>
- Findings: <数量或 No actionable findings>
```

类型对应的 Core check：

- Feature Add：新增 UI 行为是否完整接入并覆盖关键边界？
- Feature Change：新旧用户行为是否明确且兼容？
- Bug Fix：前端根因是否成立，修复是否位于正确层级？
- Refactor：渲染、状态和事件行为是否等价？
- Optimization：收益是否有测量，交互和渲染是否保持？
- Test：测试是否能在错误前端实现下失败？
- Chore：前端工程变化是否可复现、兼容且可回滚？
