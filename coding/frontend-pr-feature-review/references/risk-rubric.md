# Frontend Feature Risk Rubric

只把能由本次前端 diff 直接证明的问题放入 `风险项`。风险类型只能是 `没有完成功能目标`、`引入了新的问题`、`代码质量问题` 或 `性能问题`。

## 没有完成功能目标

满足以下全部条件时输出：

1. 能从 issue、PR、测试或现有行为证明具体的功能目标或验收条件。
2. changed logic 遗漏了实现该目标所必需的入口、状态、集成或兼容路径。
3. 能指出真实可达的用户条件和具体缺失、错误或不可用结果。
4. 能给出落在本次前端范围内的功能补全方向。

常见证据包括：

- 目标用户没有可用入口，或权限、开关和路由没有同步；
- 主流程存在，但 loading、error、empty 或提交结果导致功能无法完成；
- 只接入部分调用方，其他已声明入口仍使用旧行为；
- 请求、缓存、持久化或 UI 状态没有形成可完成的闭环；
- 行为变更遗漏旧数据、旧 URL、旧响应或关闭 feature flag 时的兼容路径。

未声明的产品偏好、可选增强和“还可以做得更多”不构成该风险。

## 引入了新的问题

满足以下全部条件时输出：

1. 问题由本次 changed frontend code 引入。
2. 存在真实可达的用户、浏览器、渲染或调用路径。
3. 能说明新的错误 UI、状态、请求、副作用、性能或可访问性结果。
4. 该结果不是 PR 明确要求的有意变化。
5. 能给出不破坏功能目标的调整方向。

重点检查：

- 新入口、默认值、权限或条件分支是否误伤旧路径；
- 重复操作、快速切换、取消、卸载和重试是否产生竞态或陈旧状态；
- 请求参数、query key、缓存失效和持久化是否与 UI 结果一致；
- 共享组件、hook、路由或公共契约的其他调用方是否回归；
- 键盘、焦点、ARIA、长文本和窄屏下是否出现可达问题。

## 代码质量问题

满足以下全部条件时输出：

1. 本次 changed frontend code 命中明确适用的 Vercel React Best Practices rule。
2. 能指出真实消费或维护路径，而不只是个人风格偏好。
3. 能说明不必要的状态、副作用、耦合、重复逻辑或脆弱契约造成的具体维护或演进影响。
4. 能给出保持 Feature 目标的可执行调整方向。

## 性能问题

满足以下全部条件时输出：

1. 本次 changed frontend code 命中明确适用的 Vercel React Best Practices 性能 rule。
2. 存在真实可达的加载、请求、渲染、交互或构建路径。
3. 能从代码证明额外 waterfall、bundle 成本、服务端工作、请求、重渲染或计算，而不只是假设“可能更慢”。
4. 能给出不破坏 Feature 目标的可执行优化方向。

## 输出门槛

每项风险必须包含：

- `具体说明`：触发或消费路径、changed logic 和具体错误、维护或性能影响；
- `具体代码`：固定到 head commit 的 GitHub 链接和逐字核心代码；
- `建议修复`：可执行的功能补全、回归消除、代码质量调整或性能优化方向。

证据不足、旧问题、个人偏好、格式和 nit 不输出。没有合格风险时写 `无风险项。`

Vercel subagent 的候选问题由 owner 复核并分类为 `代码质量问题` 或 `性能问题`；不满足对应全部条件时不输出。
