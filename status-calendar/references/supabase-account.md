# 已有 Supabase Auth 日历

本流程适用于原有的逐账号日历。该版本使用 `user_id` 区分记录，日常数据访问通过已有日历账号及其行级安全策略完成。新建私人日历使用[项目连接](supabase-auto.md)。

**保留返回位置。** 从按钮消息读取 `resume`（`month` 或 `configure`）及 `month`（`YYYY-MM`）。用户用文字提出连接时，沿用上一个日历视图与月份，没有上下文则用当地本月的月历。

授权入口有时先返回「授权已接受」，随后才提供项目列表。此时重新发现连接器并重试列项目。如果当前聊天仍无法调用项目列表，请用户将已授权的 Supabase 添加到当前消息后继续。本次等待期间保留项目选择和返回视图。

1. **发现授权和目标项目。** 查找当前可调用的 Supabase 工具。没有连接时，用插件管理搜索 Supabase 并呈现授权入口，等待用户完成授权；恢复时重新发现工具。连接器已限定项目时用该项目。账号级连接使用 `list_projects`（或等效工具）；用户已指定或只有一个可用项目时直接选用，有多个候选时按名称和项目编号让用户选一次。记录选中项目的 ref，后续操作都固定到它。若没有项目，告知需要一个项目；用户希望新建时，先确认组织、地区及费用。项目暂停时说明情况，再按用户选择恢复或换项目。
2. **检查项目。** 在选中的项目用 `get_project_url`、`get_publishable_keys` 获取项目地址及可用的现代公开 key；从工具结果仅提取 `sb_publishable_…`，优先使用启用的默认项。此过程不需要管理密钥、数据库密码或用户会话。只有旧版 key 或返回掩码时，引导用户在该项目设置中创建或启用 Publishable key，之后重新通过连接器获取。用 `execute_sql` 执行 [inspect.sql](../assets/providers/supabase/inspect.sql) 的原文，读取唯一的 `status` 字段。它只查询数据库结构与访问策略。
3. **按检查结果继续。**
   - `ready`：进入本机登录。
   - `missing`：在聊天中说明所选项目名称及将创建的 `public.status_calendars` 表和仅本人可读写的策略。经用户确认后，用 `apply_migration` 在**同一项目**执行 [supabase-calendar.sql](../assets/supabase-calendar.sql) 的完整内容，迁移名为 `initialize_status_calendar`。若连接器仅有只读权限，说明所需的项目写权限。执行完成、返回超时或收到同名对象错误后均重新运行检查；仅在新结果为 `ready` 时继续。已有部署直接复用。
   - `review`：已有同名对象与预期结构或权限不符，保留对象和本机记录，说明需要核对之处或选择其他项目。查询失败或结果无法识别时，修复权限或连接后重试检查，不能把失败当成缺表。
4. **登录和导入。** 登录前用目标项目名告知用户，若账号已有云日历将直接打开，首次同步则会导入本机状态和记录。在技能的 `scripts/` 目录执行 `python3 -B -m providers.supabase.auto_setup`。经安全的 stdin 传入以下 JSON，用同一个项目的真实工具结果替换示例。若状态是 `missing` 或 `review`，脚本只返回下一步、月份和视图；`ready` 时才会登录。

   ```json
   {
     "project_ref": "<选中的项目编号>",
     "schema_status": "ready",
     "url": "<连接器返回的项目 URL>",
     "key": "<连接器返回的公开 key>",
     "resume": "month",
     "month": "YYYY-MM"
   }
   ```

   本机窗口或交互终端接收该项目的日历账号邮箱和密码。日历账号须为该项目已确认的 Supabase Auth 用户；若用户尚无账号，给出所选项目 Authentication → Users 的位置，再从登录步骤继续。管理连接器的 OAuth 授权与此账号的身份用途不同。用户取消登录时保留当前日历；首次云端导入和原连接替换均由适配器处理。沙箱需要本机弹窗、网络或数据目录写入权限时，通过命令执行器请求相应许可。不要让用户在聊天中输入账号密码。
5. **展示结果。** 只有脚本返回 `next: "render"` 和 `connected: true` 才报告连接成功。`calendar: "existing"` 表示已打开该账号原有云日历；`calendar: "created"` 表示新建，使用实际的 `imported_days` 说明导入了多少天的记录。从技能目录按返回值运行 `scripts/render_card.py`，把原视图直接嵌回当前聊天。若数据库结构已就绪、数据 API 仍报告找不到表，检查项目的数据 API 是否启用、`public` 是否对该 API 可见，再重试读取。
